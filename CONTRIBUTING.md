# Contributing

Thanks for trying this experiment. Clear, practical feedback is welcome, especially about translation meaning, pronunciation, accessibility or browser behavior.

Before opening an issue, check existing issues and [active tasks](docs/TD.learn.md). Include the learning direction, browser/device, what you expected and reproducible steps. Use synthetic examples; do not include personal learner information. Testing a desktop viewport does not establish physical-phone compatibility.

For a source change, read [AGENTS.md](AGENTS.md), the [checkpoint](docs/WORK_CHECKPOINT.md) and relevant module guidance first. Start a small branch from current main and open a pull request. Run the checks in the [README](README.md#source-and-checks), explain what you verified and state any checks you could not run. Generated HTML must be rebuilt from canonical sources, not edited directly.

Preserve lesson content, permanent IDs, answer bindings, recordings, the seven-direction allowlist and the zero-saves requirement unless the owner authorizes a specific change. Adding an idea to the task list does not start implementation. Merges and application publication follow the repository's owner-approval rules.

Human language or pronunciation feedback should name the exact item and direction; automated checks are not fluent review. New features, extra directions, Android work and license choices need a separate owner decision.

No source-code/content license has been selected. This guidance does not grant general reuse rights or select a license.
